# MyHook v8.0

通用 LSPosed 模块，只需要在 LSPosed 里给目标 App 勾选作用域即可自动生效，按规则/智能识别修改 App 的 OkHttp 网络响应（VIP/会员状态、到期时间、次数限制等）。

## v8.0 更新：真正的零配置

- **去掉了设置里包名白名单的强制要求**。之前需要同时满足"LSPosed 作用域勾了"和"设置里也填了包名"两个条件才生效，现在**只看 LSPosed 作用域**——因为 LSPosed 本身的作用域机制已经是访问控制的唯一可靠来源，模块自己再维护一份重复的白名单没有实际意义，只会增加一步容易忘记的手动配置。设置里的包名栏改成纯可选项，只用于 `[包名] key=value` 这种精确限定规则、以及保存时自动 force-stop 对应的 App
  - **技术说明**：本来想做"作用域里加了什么 App，自动写回设置界面"，但这个方向在 Android 上做不到——模块代码是在目标 App 自己的进程里运行的，没有权限跨进程写入 MyHook 自己的私有配置文件，这是系统级的隔离，任何 Xposed 模块都绕不过去。去掉白名单要求是能达到同样效果（不用手动同步两处配置）里唯一靠谱的办法
- **智能匹配默认开启**。配合上面的改动，现在全程只需要一步：在 LSPosed 管理器里给 MyHook 勾选目标 App 的作用域，其余全自动
- **中英文 VIP/会员关键词库进一步扩充**，同时把几个风险较高的泛化词（`level`、`grade`、`usertype`、单独的"等级"/"剩余"）从智能匹配的自动扫描范围里去掉——这几个词太通用，可能命中游戏等级、积分余额这类完全无关的字段，自动模式下遇到误伤不容易发现。这几个词依然保留在"填入 VIP 完整示例规则"里，需要的话可以手动加成精确规则，由你自己确认要不要对某个具体字段生效

## v7.0 更新

- **智能匹配模式**（新开关，默认关闭）：不用手写规则，自动扫描响应里所有 JSON 字段，按内置的中英文关键词库（状态类/等级类/到期时间类/剩余次数类共四组）识别 VIP/会员相关字段并自动翻转。**类型安全**：翻转时严格保持原字段类型不变（布尔还是布尔、数字还是数字、字符串还是字符串），避免因为类型不匹配导致 App 的 Gson/Moshi 解析崩溃；日期类字段会按原有格式（`yyyy-MM-dd HH:mm:ss`、纯日期、秒级/毫秒级时间戳等）识别后替换成对应格式的未来日期，不是无脑塞固定字符串
- **反检测模式**（新开关，默认关闭，效果因 App 而异）：
  - 过滤 `Throwable.getStackTrace()` 结果里包含 Xposed/LSPosed/本模块的堆栈帧，防止 App 通过抛异常翻堆栈的方式发现注入痕迹
  - 拦截对 `XposedBridge.jar`、`/data/adb/lspd` 等特征路径的文件存在性检查，统一返回"不存在"
  - 过滤 PackageManager 返回的已安装应用列表，隐藏 Xposed/LSPosed/EdXposed 等管理器 App 和本模块自身；同时拦截直接按包名查询这些管理器的请求
- **保存设置后自动 `force-stop` 所有配置的目标包**（通过 `su` 执行），不用再手动敲命令强杀目标 App，保存完重新打开就是最新配置

## v6.2 更新

- **URL 正则不再需要 `re:` 前缀**，直接写正则表达式就行，例如 `^https?://.*api/v\d/user/.*$`；普通文本关键字（比如 `userInfo`）依然按子串匹配，两种写法自动识别，混着填也没问题
- **JSON 字段路径精确匹配**：规则的 key 里带点号就会按路径逐层定位，例如 `data.isVip=true` 只改 `data` 对象下的 `isVip`，不会动到响应体里其他地方恰好同名的字段；路径每一层同样支持嵌套字符串 JSON 和数组穿透
- **新增大批国内 App 常见字段**：年卡/月卡/周卡会员（`isyearvip`/`ismonthvip`/`isweekvip`）、永久会员（`isforever`/`islifelong`）、分级会员（`svip`/`goldvip`/`diamondvip`/`supervip`）、会员卡类型（`vipcardtype`/`cardtype`）、自动续费（`isautorenew`/`renewstatus`）、剩余天数类到期字段（`vipdays`/`memberdays`/`remainingdays`）

## v6.0 更新

- **Hook 点改为 `OkHttpClient#newCall(Request)`**，取代之前 hook 内部 `RealCall` 类的方式。`newCall` 是 OkHttp 稳定的公开 API，从 3.x 到最新版本签名都没变过，不再依赖 `okhttp3.RealCall` / `okhttp3.internal.connection.RealCall` 这种容易随版本变化的内部类名，兼容性更好。旧的 `RealCall` hook 方式保留作为兜底（`newCall` 拿不到时自动降级）
- **支持嵌套字符串 JSON**：有些接口会把子数据整个塞进一个字符串字段里（比如 `"data": "{\"isVip\":false}"`），现在规则引擎会自动识别并深入这类字符串内部继续查找、替换，支持任意层嵌套
- **JSON 字段名匹配已改为模糊匹配**：自动忽略大小写和下划线差异，`isvip=true` 一条规则就能同时命中 `isVip`、`is_vip`、`IsVIP`、`ISVIP` 等各种写法，不用逐个列举
- **示例规则新增国外常见订阅字段**：`subscribed`、`subscriptionStatus`、`planType`、`tier`、`entitlement` 等，覆盖面更广，不止国内 App 的命名习惯
- **设置界面改为白色主题**
- **⚠️ 关于"改了规则后 App 部分功能消失"**：多半是 URL 关键字填得太宽（比如直接填 `vip`、`member` 这种词），连带命中并改动了不相关接口的数据；或者像 `isInAppBuy` 这类字段本身也被 App 用来控制某些功能入口的显示与否。建议 URL 关键字尽量精确到具体接口路径，规则里对这种"多用途"字段要谨慎，逐条测试

## ⚠️ v5.0 重要修复：签名不固定导致完全不生效

之前 `build.gradle` 没有指定签名配置，走的是 Gradle 默认 debug 签名——本地没有 `~/.android/debug.keystore` 时会自动生成一个随机的。**GitHub Actions 每次运行都是全新虚拟机，没有任何缓存，导致每次编译出的 APK 签名证书都不一样。**

LSPosed 记录模块的作用域（哪个模块对哪个 App 生效）时会连同签名证书一起记录。每次重新编译签名都变，即使包名、界面上的作用域勾选都没变，LSPosed 也可能因为证书对不上而完全不生效，且不会有任何报错或日志——所有代码逻辑都不会被执行到。

v5.0 把 `app/debug.keystore` 固定提交进了仓库（`.gitignore` 里也加了例外，避免被忽略），`build.gradle` 显式指定用这个文件签名，保证每次 CI 编译出来的证书完全一致。升级后如果之前装过旧签名版本，需要先卸载再装新的（不同证书没法直接覆盖安装）。v5.0 之后签名已固定，后续版本之间可以直接覆盖升级，不用再卸载。

## 相比 v4.0 之前的改动

- **Hook 点从 `ResponseBody.string()` 改为 hook 网络调用层**：不管 App 用 `.string()`、`.charStream()` 还是 `.source()` 读响应，都能拦到，覆盖面更广
- **URL 关键字改成真正匹配请求 URL**（旧版其实是在响应体文本里搜关键字，容易造成误解）
- **规则支持按 JSON 字段名精确修改**（`key=value`），递归遍历 JSON 树找到对应字段设置新值，不再依赖纯文本替换，避免误伤同名文本
- **规则可选按包名限定**：`[包名] key=value`，多个目标 App 用不同规则也没问题
- **配置读取加了 2 秒缓存**，不再每次请求都读一次磁盘
- **跳过图片/视频/音频/octet-stream 等二进制响应**，以及超过 3MB 的响应体，避免误处理或内存问题
- **移除了无效的手动 chmod 权限代码**，权限完全交给 Manifest 里的 `xposedsharedprefs` 标记处理（这才是真正生效的机制）
- **保留旧版的纯文本替换写法**（`旧文本|新文本`），完全向下兼容旧配置

## 功能

- 设置界面动态配置目标包名（一行一个，可同时对多个 App 生效）
- URL 关键字过滤（可选，留空则不过滤）
- 规则引擎两种写法：
  - `key=value`：按 JSON 字段名递归查找并设置新值（推荐，精确不误伤）
  - `旧文本|新文本`：纯文本替换（兼容旧配置）
  - 任意一条规则前面可以加 `[包名]` 限定只在该 App 生效
  - `#` 开头的行是注释
- 值的写法：`true` / `false` / `null` / 数字 直接写；字符串可以直接写（如 `2099-12-31 23:59:59`），也可以用双引号包起来
- 内置一套覆盖常见字段命名习惯的 VIP 示例规则（isVip / is_vip / vip / isMember / vipLevel / vipExpiredTime / expireTime / showAd / remainCount 等），点"填入 VIP 完整示例规则"一键填入，再按实际抓包结果删减

## 使用

**最简单用法（零配置）**：
1. 安装 APK
2. LSPosed 管理器 → 勾选 **MyHook** 模块 → 作用域勾选目标 App
3. 强制停止目标 App 后重新打开
4. 完事——智能匹配默认开启，会自动识别常见 VIP/会员字段

**需要精确控制时（可选）**：
1. 打开 **MyHook**，按需填写：目标包名（用于 `[包名]` 规则限定和自动 force-stop）、URL 关键字缩小匹配范围、手写 `key=value` 精确规则
2. 保存（会自动 force-stop 包名栏里列出的 App）
3. `adb logcat | grep MyHook` 看是否命中（会打印命中的 URL）

## 规则示例

```
# 会员状态
isVip=true
vipLevel=9
memberStatus=1

# 到期时间
vipExpiredTime="2099-12-31 23:59:59"
expireTime="2099-12-31 23:59:59"

# 次数限制 / 广告
showAd=false
parseVideoRemain=9999

# 只对某个 App 生效
[com.example.anotherapp] userLevel=99

# 精确路径匹配，只改 data 对象下的 isVip，不动别处同名字段
data.isVip=true
data.user.vipLevel=9

# 兼容旧版纯文本替换
"isVip":false|"isVip":true
```

URL 关键字可以直接写正则，例如：
```
^https?://.*api/v\d/user/.*$
```
不需要任何前缀，普通文本关键字（如 `userInfo`）和正则可以混着填。

## 已知限制

- 只处理响应体是 JSON/文本的接口，不处理请求体、请求头、二进制协议（protobuf 等）
- 极少数 App 会用非 OkHttp 的网络库（Cronet、自研 HTTP 客户端等），这类接口拦不到
- `key=value` 规则命中后会用 `JSONObject.toString()` 重新序列化整个响应体，字段顺序、数字精度可能有细微变化（一般不影响 App 正常解析）
- **反检测只覆盖堆栈痕迹、特征文件、管理器 App 列表这几个常见检测点，不是完整的 Root/Xposed 隐藏方案**（不处理 su 二进制检测、系统属性 `ro.build.tags`、内存扫描等），如果设备上已经装了专门的 Root 隐藏模块（比如你列表里的 NoActive），两者可以同时开，互不冲突
- **智能匹配是关键词启发式识别，不保证 100% 准确**，遇到误判可以关掉智能匹配、改用手写的 `key=value` 精确规则
- 如果 App 调用了 `Call.clone()` 再发起请求（部分重试逻辑会这样做），克隆出来的请求不会被拦截，这种情况比较少见
- 项目仅用于学习/研究/自用调试，不建议用于生产环境或分发给他人
